# Take Me Out — מקור אמת (24.11.2026, חגי)

קרא את כל הקובץ לפני שאתה מתחיל. הוא **גובר על `docs/brief-20261115.md`** ועל כל מסמך תכנון ישן יותר שסותר אותו. כל מה שלא שונה כאן — נשאר בתוקף מהבריף הקודם.

## 0. מה השתנה מאז 15.11 (קרא קודם)
- **לב המוצר הוא מתכנן המסלולים ב-AI** — לא תוסף. הלקוח מספר חלום בעברית ("שבוע חלומי של מפרצים נסתרים"), ומקבל בחזרה מסלול מלא, מפה חיה ותמונות אמיתיות מהמקום. זה מה שמבדל אותנו, וזה מה שהלקוח פוגש ראשון.
- **עיצוב פרמיום מחייב + קול "גילוי"** — מוגדר ב-`docs/specs/design-system.md`. כל מסך עובר דרכו, בלי יוצא מן הכלל.
- **מקור הסירות: גם וגם** — מפעילי סירות מנוע קטנים שחגי מגייס ישירות (דרך ממשק המפעיל) כבר בפיילוט, ו-MMK כמלאי מאומת משלים.
- ה-"AI" של הבריף הישן (עוזר תמיכה + תרגום דוחות תקלה ליוונית) נשאר בתוקף — אבל הוא משני למתכנן המסלולים.

## 1. כללי עבודה (ללא שינוי — מחייב)
- כל מה שאתה כותב בטרמינל — בעברית. שמות קבצים, ענפים ופקודות באנגלית.
- הוראת ברזל: בכל דוח לחגי — שמות מלאים ומספרי טלפון מלאים, בלי קיצורים.
- סודות (מפתחות, טוקנים) רק דרך הלוח או משתני סביבה. אף פעם לא בצ'אט, בקוד או בקבצים ב-repo.
- לפני כל פריסה: כל הבדיקות עוברות → גיבוי → בדיקה בפרודקשן → פריסה. נקודת חזרה בכל דוח. גיבוי נכשל = לא פורסים.
- מתגים (feature flags) לכל דבר שפונה ללקוח או שולח הודעות/כסף — כבויים עד שחגי מאשר.
- בלי מחיקות של נתונים — סימון/הסתרה בלבד.
- לא עובדים בתיקיית Temp. עבודה רק בתוך תיקיית הפרויקט.
- תקשורת עם חגי: כל מה שצריך אותו — מועתק ללוח. צליל רק כשצריך אותו. הסוכן של הפרויקט הזה: שלושה צפצופים (הריזורט — אחד, זכויות המורה — שניים). כשצריך פעולה בדפדפן — קודם רק הקישור ללוח, לחכות ל"הודבק", ואז את ההמשך.
- כשההנחיה ארוכה — spec בתיקייה `docs/specs` והדבקה קצרה מפנה אליו.

## 2. הגוף המשפטי והכסף (ללא שינוי)
- מותג: Take Me Out. דומיין: takemeout.co.il. מייל: hagai@takemeout.co.il.
- הגוף המשפטי: מגדל דנילוב בע"מ (ח.פ. 514942119). אין חברה יוונית (IKE) ולא תהיה.
- כל הכסף נגבה בישראל בלבד, דרך Grow (סליקה) ו-Morning (חשבוניות) הקיימים. לא פותחים חשבונות נפרדים.
- מחירים ביורו + מחשבון לשקלים. תשלום בשקלים לפי שער יום התשלום + מרווח קבוע. עמלות סליקה על הלקוח. כל התוספות (ניקיון, פיקדון, מה שהמפעיל גובה במזח) נגבות מראש — בלי הפתעות.
- הכנסה: עמלה מהמפעילים. דמי שירות מהלקוח — בונוס, סכום לקביעה. החלק של הלקוח נשאר אצלנו בביטול.
- תשלום למפעיל: חצי בהזמנה, חצי חודש לפני ההפלגה. הלקוח משלם יום לפני כל תשלום למפעיל. ביטולים לפי מדיניות המפעיל + גילוי מורחב.
- כסף נשמר במספרים שלמים (אגורות/סנטים) עם השער והמרווח של כל תשלום.

## 3. מתכנן המסלולים — הלב (חדש)
### עיקרון: המנוע שלנו, לא ה-AI
- כל הגיאוגרפיה — איים, מפרצים, בסיסי יציאה, טברנות, מרחקים ימיים, ניתוב במים — נתונים שלנו ב-Supabase. המסלול נבנה **אלגוריתמית** מהנתונים. ה-AI לעולם לא ממציא מקומות, מרחקים או מפרצים.
- ה-AI (Claude API, דרג חסכוני) עושה שתי פעולות דקות בלבד: (1) טקסט חופשי של הלקוח → העדפות מובנות (ימים, קצב, סגנון, תקציב, רמת רישיון, נקודת יציאה); (2) כתיבת הנרטיב המגרה לכל עצירה לפי הקול ב-design-system. קלט/פלט קטן, ניתן ל-cache.
### תאריכים וזמינות (חדש — 24.11)
- המתכנן מקבל טווח תאריכים (הגעה→עזיבה), בדרך כלל נגזר מהטיסות הישירות מישראל, ובונה את המסלול שיתאים למספר הימים. תומך בבקשה מפורשת: "תכנן מסלול מתאריך X עד תאריך Y".
- התאריכים משפיעים גם על זמינות (סירה/מפעיל פנויים בתאריכים האלה) ובהמשך על עונה ומחיר. מסלול שלא נכנס לטווח — מותאם/מקוצר עם הסבר ללקוח.
- מתחבר ללוח הטיסות (עדכון שבועי) להמלצת בסיסי יציאה לפי טיסות ישירות מישראל או חיבור קצר מאתונה.

### בקרת עלות (מחייב — נגזר מהחשש שסקרנים "יעננו" עם המערכת כל החורף)
- **מסלולי דגל מוכנים מראש** — נוצרים פעם אחת, נגללים חינם לנצח, בלי שום קריאת AI. רוב המבקרים לא יפעילו את המנוע בכלל. כל מסלול דגל נושא הוכחה חברתית (ביקורות/טסטימוניאלים — "15 משפחות כבר עשו את זה ונהנו").
- **Cache**: חלום דומה למישהו שכבר שאל → מוגש מהמטמון בלי קריאת AI.
- **שער קליל**: 2–3 תכנונים חינם למכשיר, ואז כניסה (קוד חד-פעמי בוואטסאפ) כדי להמשיך. מסנן בוטים וסקרנים — וכל מי שנרשם הוא ליד חם שחגי/אלכס יכולים ללוות.
- **תקרת תקציב חודשית** — חריגה → נפילה אוטומטית למצב "מסלולי דגל בלבד" (בלי AI) עד איפוס.
### תמונות אמיתיות (זה מה שגימיני עשה, וזה מה שחסר בדמו)
- שילוב: Google Places Photos API לכיסוי רחב של כל מפרץ/טברנה/מקום + ספרייה מבוקרת שלנו לתמונות הדגל של המסלולים המובחרים.
- כל תמונה נקראת פעם אחת, נשמרת ב-Supabase Storage ומוגשת מה-CDN — אפס עלות חוזרת. שמירת ייחוס/מקור לפי תנאי Google Places.
### מפה
- Mapbox Satellite GL. המסלול מצויר מעל נתיבי מים אמיתיים (בלי לחצות אי ביבשה), זום-אין לכל עצירה, **אותה סירה** לכל אורך המסלול.

## 4. מקור הסירות והמפעילים (מעודכן — "גם וגם")
- גיוס ישיר של מפעילי סירות מנוע קטנים דרך **ממשק המפעיל** — כבר בפיילוט. מסכי הממשק: הזמנות והכנסות, יומן זמינות, רישום הסירות, מסך הצטרפות ("המערכת עובדת, הצטרף").
- MMK כמלאי מאומת משלים (רק Silver/Golden). sandbox עד סוף מרץ 2027, נתונים אמיתיים מאפריל 2027 (איש קשר: Zdenko). בלי התחייבות (דמי API / בלעדיות) עד שתתקבל החלטה מול הרווח והזמינות.
- הכול מאחורי מתאם הזמנות אחיד (`lib/booking`): mock → direct → mmk, בלי לשנות את שאר הקוד.
- אלכס (Alexandros Bertsiadis): אין תלות במערכת שלו ואין API שלו בפיילוט. עמלת B2B פתוחה לעתיד. יכול לסייע ידנית ב"שידוך" סירה לפונה רציני שרוצה לסגור את הקיץ הקרוב.

## 5. השלד שנבנה עכשיו — שלושה חלקים (מעל שלב 0 הקיים)
כל השלושה בעיצוב ובקול מ-`docs/specs/design-system.md`, עברית/RTL, PWA.
1. **מפה חיה** — Mapbox Satellite GL + ציור ואנימציית מסלול מעל מים אמיתיים, זום לעצירות, אותה סירה.
2. **מתכנן המסלולים** — מנוע דטרמיניסטי מעל נתוני Supabase + שכבת Claude דקה → מסלול + מפה + תמונות אמיתיות + נרטיב. מסלולי דגל מוכנים מראש עם ביקורות.
3. **הזמנות/תשלום + ממשק המפעיל** — Grow+Morning אמיתיים אך מאחורי מתגים כבויים עד אישור; ממשק המפעיל לגיוס ישיר.

## 6. כניסה, וואטסאפ, שפה (ללא שינוי)
- כל מסע הלקוח בעברית. האנגלית הראשונה שהוא פוגש היא בצ'ק-אין בסירה.
- כניסה: קוד חד-פעמי בוואטסאפ כברירת מחדל, גוגל/אפל כאפשרות. Green API על מספר ישראלי ייעודי, מאחורי שכבת שליחה אחת (`lib/messaging`) כדי לאפשר מעבר ל-WhatsApp Cloud API בלי לשנות קוד.
- הודעות תפעוליות — בכל זמן. שיווק ותזכורות תשלום לא דחופות — רק אחרי שבת וחג. פרטי קשר ללקוח: ישראליים בלבד.

## 7. פתוח — לא להחליט לבד (מעודכן)
- ביטוח (קדר), בדיקה משפטית לפני השקה, איש גיבוי כשחגי לא זמין, גובה דמי השירות ללקוח, אזורי ההשקה ביוון.
- מנוע ה-AI: Claude API דרג חסכוני — לאישור סופי מול עלות בפועל.
- תקרת התקציב החודשית של המתכנן — סכום לקביעה.

אחרי שקראת את הבריף הזה ואת `docs/specs/design-system.md`: דוח קצר בעברית ללוח — מה הבנת, באיזה מהשלושה אתה מתחיל, ומה נקודת החזרה. לא לבנות עד שחגי נותן פקודת ביצוע. ואז שלושה צפצופים.
